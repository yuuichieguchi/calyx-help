最終更新日: 2026 年 10 月 6 日

Calyx は、ローカルで完結する macOS ターミナルアプリケーションです。
本ページでは、Calyx が取り扱うデータと外部通信について説明します。

## 利用者情報の収集

Calyx は、利用者の識別情報、行動ログ、クラッシュレポート等を一切収集しません。
Calyx は、解析（アナリティクス）やテレメトリを送信しません。

開発者は、Calyx の起動時刻・利用機能・入力内容を把握する手段を持っていません。
任意機能の [Usage Tracking](#claude-code-の使用量の記録) が記録する Claude Code のトークン数も利用者のマシン内に保存され、開発者には届きません。

## ローカルに保存される情報

Calyx は、起動状態の復元と機能の動作のために、利用者のマシン内に次の情報を保存します。
これらは利用者のマシンの外には送信されません。

- 開いていたタブ、スプリット、各タブの作業ディレクトリ、動かした Mission Map のカードの位置（セッション復元用。herdr ワークスペースから開いたタブについては、再起動後に再接続できるよう herdr のソケットパスと herdr 側のペイン ID も含む。herdr のターミナル ID は保存されない）
- 永続セッションの管理情報（セッション一覧と作業ディレクトリ。ローカルの `calyx-session` デーモンが保持し、永続セッションを有効化した場合のみ。標準では無効）
- セッション履歴ファイル（`~/.calyx/state/history/` 以下。**Persist session history to disk** を有効化した場合のみ。標準では無効）
- ターミナルのスクロールバック（メモリ上、ターミナルセッション内）
- コマンドログの記録（コマンド行、終了ステータス、キャプチャした出力。**Track shell commands** がオンの間だけメモリ上に保持され、標準ではオン。ディスクには書き込まれず、Calyx の終了時に破棄されます。既知のシークレットのパターン（トークン、パスワード、API キー、JWT）は保存前に redaction されます）
- AI Agent IPC のメッセージ（本文を含む）と、エージェントが書き込もうとしたファイルのパス（Mission Map の表示用。メモリ上にだけ保持され、メッセージは直近 512 件、パスは直近 256 件まで。ディスクには書き込まれず、Calyx の終了時に破棄されます）
- コマンド追跡用のシェル統合スクリプト（`~/Library/Application Support/Calyx/shell-integration`）
- AI エージェント連携用の設定（各エージェント自身の設定ディレクトリに書き込まれます。`~/.claude.json`、`~/.codex/`、`~/.config/opencode/`、`~/.hermes/`、`~/.grok/`。`calyx-ipc` と `calyx-mcp` の二つのエントリからなり、それぞれローカルサーバーのベアラートークンを含みます。設定ファイルを持たない pi については、pi が読み込んで実行する TypeScript の拡張 `~/.pi/agent/extensions/calyx.ts`）
- Claude Code のトークン使用量（`~/Library/Application Support/Calyx/usage/usage.sqlite`。利用者本人だけが読めます。**Usage Tracking** をオンにした場合のみで、標準ではオフ。トークン数と、それが属するモデル、effort、スレッド、エージェントの種類、セッション ID、各セッションのプロジェクトのパスと作業ディレクトリ、Claude Code のトランスクリプトファイルのパス、トークン数を受信した時刻、Claude Code の各プロセスの開始時刻と開始の種別（新規開始など）、トランスクリプト内の各実行の開始と終了の時刻、トランスクリプトを読み進めた位置を保存します。会話の本文は保存しません。Usage Tracking をオフにしても残り、**Delete Usage Data…** で消去するまで保持されます。消去後もファイルは残り、それまでに受信した Claude Code のプロセスを識別する SHA-256 ダイジェスト、記録を再開した時刻、記録がオンかどうかだけを保持します。ダイジェストは、そのプロセスの消去前の使用量を数え直さないためのものです。Calyx が読めなくなったデータベースは同じフォルダに `usage.sqlite.corrupt-…` として残り、**Delete Usage Data…** では消えません）
- Claude Code 自身の設定ファイル（`~/.claude/settings.json`）に追加するテレメトリの設定（**Usage Tracking** と **Enable AI Agent IPC** が両方オンの間だけ。`env` の九つの項目と `otelHeadersHelper` からなり、Claude Code のメトリクスのエクスポーターを `127.0.0.1` 上の Calyx のサーバーに向けます。どちらかをオフにすると取り除かれますが、Calyx の終了時には取り除かれません）
- Claude Code がそのトークン数に添えて提示するベアラートークン（`~/Library/Application Support/Calyx/usage-otel-headers.json`。利用者本人だけが読めます。Usage Tracking を初めて使うときに作成され、以後は残ります）
- Settings の **MCP Apps** で追加した MCP サーバー（`~/Library/Application Support/Calyx/mcp-servers.json`。利用者本人だけが読めます。環境変数の値、リクエストヘッダー、OAuth のトークン、クライアントシークレット、登録したクライアント ID はログインキーチェーンに保存されます）
- MCP App がエージェントに送る画像（一時ディレクトリの `calyx-mcp-apps` フォルダに書き出されます）
- AI Agent IPC がオンの間に承認フックが Calyx に渡すツール呼び出しと、それに対する Calyx の応答（Claude Code と Codex では許可プロンプトごと、Grok ではすべてのツール呼び出し。フックの実行中に一時ディレクトリのファイルへ書き出され、フックの終了時に削除されます。**Show agent tool prompts in the approval banner** がオフでも書き出されます。フックが強制終了された場合はファイルが残ります）
- ブラウザサーバーの接続情報（`~/.config/calyx/browser.json`）
- LSP プロキシ用の言語サーバープロセス（バックグラウンドで動作）
- ブラウザタブのストレージ（タブを閉じると破棄される非永続ストレージ）

## 外部との通信

Calyx が能動的に行う外部通信は、次のものに限られます。

### 1. 自動アップデート（Sparkle）

直接ダウンロード版は、起動後に Appcast を取得して新しいバージョンの有無を確認します。

- 取得先: `https://yuuichieguchi.github.io/Calyx/appcast.xml`
- 取得内容: バージョン情報、リリースノート、配布物の URL
- 配布物は公開鍵による署名検証を行ったうえでインストールされます

### 2. リリースアセットのダウンロード

更新を受け入れた場合、Calyx は GitHub Releases から最新版の配布物をダウンロードします。
これは利用者が更新ダイアログで承認した時点で発生します。

### 3. 言語サーバーの自動インストール（任意）

Settings で **LSP Proxy** の自動インストールを有効化している場合、不足している言語サーバーをパッケージマネージャ経由でダウンロード・インストールします。
この機能は標準では無効です。

### 4. 利用者操作によるブラウザタブのアクセス

ブラウザタブで開いた URL へのアクセスは、利用者の操作によるものであり、通常のウェブブラウザと同様の通信が発生します。
ブラウザタブのストレージは非永続で、タブを閉じると破棄されます。

### 5. 利用者操作によるリモートセッションの SSH 接続

リモートセッションの作成や接続、および `calyx-session remote-install` の実行時には、利用者が選んだホストへの `ssh` が起動されます。
これ以外にリモートセッションが通信を発生させることはなく、利用者が開始しない限り接続は行われません。

### 6. 利用者が Settings で追加した MCP サーバー

Settings の **MCP Apps** ペインには、利用者が自分で追加またはインポートした MCP サーバーが並びます。
Calyx がこれらに接続するのは、**Enable AI Agent IPC** がオンで、かつそのサーバーのスイッチがオンの間だけです。
出荷時に設定済みのサーバーはありません。

- HTTP サーバーへは、入力した URL に、入力したヘッダーを付けて接続します。ワークスペースのルートを求めるサーバーには、呼び出し元ペインの作業ディレクトリを送ります。
- stdio サーバーは、入力したコマンドと環境変数でローカルプロセスとして起動します。そのプロセスがどこへ接続するかは、プロセス側に依存します。
- OAuth を必要とするサーバーへのサインインでは、サーバーの認可メタデータを取得し、必要に応じて認可サーバーに Calyx をクライアントとして登録し（対応していれば `https://getcalyx.app/oauth/mcp-client.json` で自身を識別し、そうでなければ動的登録を行います）、既定のブラウザで認可ページを開き、認可コードをトークンと交換します。リダイレクトはループバックインターフェイスのリスナーに戻ります。ポートはランダムで、オプションをオンにした場合は 41890 番です。サインアウトはトークンをローカルで削除するだけで、サーバーには何も送りません。
- MCP App が表示するビューは、その接続を通じてサーバーが提供する HTML から描画されます。Calyx が表示のために Web から何かを取得することはありません。ビューが要求を送れるのは、サーバーがそのビューに宣言したドメインだけで、宣言がなければどこにも送れません。ビューにはテーマの配色とフォント、ロケールとタイムゾーン、ツールの引数と結果が渡されます。
- アプリが開こうとするリンクは、利用者が承認した後にだけ既定のブラウザで開きます。

## ローカルで稼働するサーバー

Calyx は、自身のプロセス内に複数のローカルサーバーを内蔵します。
これらは外部ネットワークには公開されず、ループバック (`localhost`) でのみ待ち受けます。

- **AI Agent IPC MCP サーバー**: 同一マシン上の AI エージェントとの通信用。同じポートで、**MCP Apps** に設定した MCP サーバーを公開する `/calyx-mcp` エンドポイントと、Claude Code のトークン数を受け取る `/usage/v1/metrics` エンドポイントも提供します。トークン数を保存するのは **Usage Tracking** がオンの間だけで、それ以外は破棄します
- **OAuth リダイレクトリスナー**: MCP サーバーへのサインインの間だけ、ループバックインターフェイスで待ち受けます
- **ブラウザ自動化サーバー**: `localhost:41840`、`calyx browser` CLI からのアクセス用
- **セッションデーモン（`calyx-session`）**: Unix ドメインソケットのみで待ち受ける独立プロセスで、ネットワークポートは開きません
- **セキュア入力用ソケット**: 永続セッションがパスワード入力待ちかどうかを伝えるために起動のたびに一時ディレクトリに作る Unix ドメインソケット（`$TMPDIR/calyx-secure-input-<pid>.sock`）で、利用者本人だけが読み書きでき、流れるのはそのオンとオフの状態、ペインのセッション ID とサーフェス ID、プロトコルのバージョン番号だけです

外部からの接続を受ける構成ではないため、ファイアウォール越しの通信は発生しません。

## herdr への接続

herdr（別のターミナルマルチプレクサ）が利用者のマシンにインストールされ、動作している場合、Calyx はそれを自動的に検出して接続します。
オフにする設定はありません。
herdr を動かさなければ、この接続自体が発生しません。

接続に使うのはローカルの Unix ドメインソケットだけです（例: `~/.config/herdr/herdr.sock`）。
ネットワーク通信ではなく、マシンの外に出るものはありません。
Calyx はこの接続を使って、herdr のワークスペースを Session Browser に一覧し、herdr 上で動くエージェントをエージェントサイドバーに表示します。

herdr TUI が Calyx のペインで動いているかを判定するため、Calyx は Session Browser を更新するたびにプロセス一覧を読みます。
コマンドライン引数と環境変数を読むのは、`herdr` という名前のプロセスだけです。
読むのは利用者本人のプロセスに限られ、読んだ内容は保存されず、マシンの外にも出ません。

## AI エージェントとのやり取り

Calyx を介して AI エージェント（Claude Code、Codex CLI、OpenCode、Hermes、Grok、pi）を利用した場合、入力されたプロンプトや受信したレスポンスは Calyx を経由してターミナル上に表示されますが、Calyx 自体がそれらを記録・送信することはありません。

各エージェントがどのようなデータを外部 API に送信するかは、それぞれのエージェント提供者のプライバシーポリシーに従います。

## Claude Code の使用量の記録

Usage Tracking は標準ではオフです。
オンの間、Calyx は `~/.claude/settings.json` にテレメトリの設定を追加し、Claude Code がトークン数をループバックインターフェイス上の Calyx のサーバーへ送るようにします。
Calyx が設定するのは Claude Code のメトリクスのエクスポーターだけで、送信先はこのループバックアドレスだけです。
この設定は、設定が置かれている間に Mac 上で開始されたすべての Claude Code セッションに適用されます。
Calyx の外で開始したセッションも対象になり、Calyx が動いていない間も設定はファイルに残ります。

Claude Code が送る内容のうち Calyx が保存するのは、[ローカルに保存される情報](#ローカルに保存される情報)に挙げたトークン数とラベルだけです。
受信できなかったトークンを数えるため、Calyx は、記録対象の各セッションについて Claude Code が `~/.claude/projects/` 以下に保存しているトランスクリプトファイルを読みます。
そこから保持するのは、タイムスタンプ、作業ディレクトリ、モデルごとのトークン合計だけです。
プロジェクトのルートを求めるために、その作業ディレクトリで `git` も実行します。
これらの情報が利用者のマシンの外に出ることはありません。

テレメトリを有効にした Claude Code 自体の動作は、Claude Code のドキュメントとプライバシーポリシーに従います。

## Diff レビューコメントの送信先

サイドバーの Git ビューで作成したレビューコメントは、利用者が **Submit Review** で送信先に指定した AI エージェントのターミナルタブにのみ送られます。
GitHub などの外部サービスには送信されません。

## 配布形態による違い

- **Homebrew でインストールした場合**: Sparkle による自動更新は無効で、更新は `brew upgrade` 経由になります。Appcast の取得は行いません。
- **直接ダウンロード版**: 上記「自動アップデート」「リリースアセットのダウンロード」が発生します。

## ポリシーの変更

本ポリシーは、機能追加や仕様変更に伴い改定されることがあります。
改定後のポリシーは、本ヘルプサイト上での掲載をもって効力を生じます。
